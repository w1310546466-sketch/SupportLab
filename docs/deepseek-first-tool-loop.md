# 第一条真实 Agent 调用：谁决定，谁执行，谁验收

2026-10-05，SupportLab 已接通你本地配置的 `deepseek-flash`。
本节只学习 Agent 与运用 AI 的方法，不需要补前后端或通用工程基础。
这是一份首次接入的历史记录。2026-10-06 新增受控答案检查，当前行为见 [事实、结论与待核实事项](answer-evidence.md)。

## 模型与程序的分工

以前的 `agent-mock` 使用手写条件决定下一步。现在 `agent` 把问题、三个工具的说明和已有结果交给 DeepSeek，由模型选择工具和参数。
模型提出调用后，本地程序检查名称、参数、账号范围与预算，执行工具，再把结果交回模型。
模型不能直接访问数据库，不能通过工具参数更换账号。
这符合 [DeepSeek 官方工具调用流程](https://api-docs.deepseek.com/guides/tool_calls/)：模型返回调用请求，应用执行并提供反馈。

工具调用编号 `call_...` 用来配对一次调用与它的结果；`req_demo_018` 则是要查询的模拟业务请求编号。
两个编号用途不同，都是帮助程序与模型准确对应资料。

## 本次实际轨迹

| 模型请求 | 模型提出的动作 | 本地执行与反馈 |
| --- | --- | --- |
| 第 1 次 | 同一条回复提出 `get_request_record` 与 `get_account_state` | 顺序执行两个工具；取得配额错误码、历史时间、频率 2/60、配额 1000/1000 |
| 第 2 次 | `search_docs` | 按模型提出的查询和服务版本检索，返回配额规则、同案例说明及频率规则 |
| 第 3 次 | 最终答复 | 模型判断“月度配额耗尽”；程序检查协议、引用来源与必需证据是否齐备 |

**3 次模型请求、3 次工具调用、4 轮本地循环**：第一条模型回复包含两个工具请求，所以本地用了两轮分别执行，第二轮没有再次请求模型。
这里的 `decision_turns` 是程序处理动作的轮数，不是模型网络请求数。
一条模型回复提出多个调用也不等于本地并行执行；当前实现逐个执行，并把整批结果返回后才请求下一条模型回复。

本次用时约 9.6 秒，供应商返回输入 4248 / 输出 727 tokens，总计 4975。
这是累加每次请求的用量；后续请求包含之前的对话和工具反馈，所以输入 token 往往会增加。
没有把 token 数当成实际账单，也没有以一个案例计算稳定成功率。

## 本次实际答案，以及需要修正的部分

有支持的结论是：**在 2026-09-27 02:01 UTC 的模拟请求中，月度用量 1000/1000，频率仅 2/60，结合错误码和规则，支持月度配额耗尽。**
这不表示你的 DeepSeek 额度耗尽，也不是今天的实时业务状态。

模型还提出“申请额外配额”，但当前资料没有说明这个服务是否支持该操作；它把同案例的文档说明说成“另一条构造记录”，也可能让人误以为获得了独立证据。
另外，历史重置日期 10 月 1 日已经过去，今天的答复不应直接说“等到 10 月 1 日”而省略历史前提。
完整原文保存在 [运行报告](../reports/deepseek-018-2026-10-05.json)，逐项核对见 [审查记录](../reports/deepseek-018-review-2026-10-05.md)。

这个案例展示了三个独立的验收问题：工具是否按规则执行，根因是否有证据，建议是否也有依据。
当前代码已经检查前一项及最低证据条件，后一项仍需要评分规则和人工抽查。不能看到 `completed` 就认为全都正确。

## 已完成的工程保障

真实模型与 mock 共用执行器；白名单、参数和账号范围继续由代码控制。
SDK 固定为 `openai==3.24.0`，采用 DeepSeek 官方示例的兼容调用方式，地址固定在 DeepSeek 官方域名。
非思考模式用于本次最小工具循环；不保存内部思维过程。
配置通过本地 `.env.local` 或环境变量读取，环境变量优先；密钥不写入报告。

默认最多 4 次模型请求、每次输出 768 tokens、4 次工具调用、8 轮本地循环，自动重试关闭。
模型单次进程时限 25 秒，SDK 网络超时设置为 20 秒，工具单次 2 秒。
适配器在动作间检查 110 秒期限；这不等于所有程序操作共享一个强制中断计时器。
网络失败、用量不明或不完整输出不会伪装为正常答案；失败调用的 token 若未返回，则标为未知。

离线程序验证 98/98 通过，含原有 82 项和新增 16 项；20 条 mock 开发场景仍全部通过。
离线测试的假 SDK 响应不能证明真实模型行为；本次只有上述一条真实路径完成试跑。

## 运行方式

在项目目录运行，已有配置无需重填：

```powershell
# 无网络，仅检查配置是否齐备
.\.venv\Scripts\python.exe -m supportlab check-model-config
# 会实际请求 DeepSeek，消耗 API 额度
.\.venv\Scripts\python.exe -m supportlab agent req_demo_018 --output reports/my-deepseek-run.json
# 以下为离线回归，不请求模型
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -m supportlab eval-mock
```

实际回复可能变化。单次运行不自动重试；不要为得到满意答案无记录地反复运行。
报告输出路径仅允许项目 `reports` 目录下的 JSON 文件，避免覆盖配置或源文件。
