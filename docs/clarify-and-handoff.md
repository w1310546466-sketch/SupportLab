# Agent 查不下去时，怎样给出有用的交接说明

2026-10-06。本次继续学习 Agent 的证据判断、停止行为和失败分析，不补前后端基础。

后续已实现有限格式纠正；本页保留这一阶段的失败事实，最新结果见 [下一阶段记录](format-recovery.md)。

## 从一个具体例子开始

你让 Agent 排查 `req_demo_018`。它查到请求记录中的错误码是 `MONTHLY_QUOTA_EXHAUSTED`，意思是“月度配额耗尽”，但查询对应账号快照时返回“未找到”。

此时不能把以前正常演示里的 `1000/1000` 搬过来。这次没有查到用量，错误码只能作为线索，还不足以完成我们要求的交叉核验。

现在程序会整理三部分：

| 部分 | 这个例子应当写什么 |
| --- | --- |
| 已查证 | 请求存在，记录中有上述错误码；账号工具执行过，但没有找到对应快照 |
| 仍缺少 | 同一请求、同一时刻、同一服务版本的账号用量；不能把未知用量写成 0 |
| 如何补证据 | 由有权限的服务维护者补充该次历史记录，再重新排查 |

“账号记录没找到”不等于“账号不存在”，也不等于“用户没有余额”。“查询失败”则是另一回事：可能是查询工具的数据源不可用，不能把它当作用户 API 失败的根因。

## 模型与程序各做什么

模型仍选择查哪些工具，并提出最终动作及理由，例如“缺账号快照，需人工核实”。程序检查这个理由能否被本轮反馈支持，再从工具记录整理文字。

数据流是：**用户给编号 → 模型提出查询 → 程序执行并回传 → 模型提出停止理由 → 程序核对并生成交接说明。**

如果模型还没查账号，就声称“账号快照找不到”，程序拒绝这个理由。追问/转人工也需要依据，不能成为跳过证据检查的出口。

追问用于缺少编号、需用户核对编号等情况；转人工用于缺少内部记录、证据冲突、工具失败等情况。当前只打印这些结果，不联系真实客服、不创建工单，也尚不能续接同一任务。

## 这次实际运行的结果

离线演示 **5/5** 符合预期，使用真实本地工具和手写决策脚本，不调用模型：

| 构造情况 | 实际行为 |
| --- | --- |
| 没有请求编号 | 追问编号，不猜编号 |
| 请求存在，账号快照没找到 | 转人工，列出缺少的历史记录 |
| 错误码称配额耗尽，快照却是 999/1000 | 列出两份不一致的证据，要求核对 |
| 查询数据库不可用 | 说明工具失败，不推断业务根因 |
| 未查账号就声称快照缺失 | 拒绝该停止理由，保留“尚未查询”的真实状态 |

全部程序测试 **139/139** 通过，原 mock 场景仍为 **20/20**。这些数字不是模型准确率。

另外真实调用了一次 DeepSeek，使用临时副本中的“缺账号快照”场景：

1. 模型第一轮同时提出查请求和账号，程序实际执行两个工具。
2. 请求查询成功，账号快照未找到。
3. 模型第二轮返回的最终文字未能被解析为所需 JSON，程序记录 `model_invalid_json` 并停止。
4. 程序仍从已有工具证据生成交接说明，没有丢掉查询结果，也没有编造用量。

因此这次“模型正确提交停止理由”的验收是 **0/1**，不能因为最终也显示转人工就改成通过。程序在模型失败时保留证据的行为实际生效了；正常提交停止理由的真实路径仍待验证。

本次共 **2 次模型请求、2 次工具调用、3 轮动作**，约 **4.95 秒**；输入 **3135**、输出 **136** tokens。未测金额，无自动重试。保存了 [真实失败报告](../reports/deepseek-stop-missing-account-2026-10-06.json) 和 [离线演示报告](../reports/stop-demo-2026-10-06.json)。

日志没有保存未解析的最终原文，因此目前只能确定格式解析失败，不能断言是代码围栏、缺少括号还是其他具体格式问题。这个场景已参与开发，不是保留测试。

## 可选练习：区别三种“缺资料”（15–20 分钟）

在项目目录运行，不消耗 API 额度：

```powershell
.\.venv\Scripts\python.exe -m supportlab stop-demo
```

比较 `missing-account`、`tool-failure` 和 `premature-stop`，用自己的话各写一句：现在确实知道什么，还不能确定什么，下一步需要谁提供什么。

参考判断：第一种查过但没找到；第二种工具没有成功完成查询；第三种根本没查账号。三者都不能凭空给出账号用量。能指出这三种差别并解释为何不能直接诊断，即达到本次练习目标；不用补做基础编程练习。

命令退出码 0 表示演示行为符合预期，包含“故意错误被拦下”；1 表示存在未符合预期的案例；2 表示参数或准备出错。

## 本次运用 AI 的方法

给 AI 的要求要同时写明“应该做什么”和“哪些反例必须拒绝”，例如：

> 当账号工具返回未找到时，列出已知请求线索与缺失记录，不填写账号用量。请同时验证一个反例：模型没查账号就声称缺记录，必须被拦下。报告实际运行结果，失败也要保留。

这比只说“不要编造”更便于验收。本次也实际保留了模型格式失败，没有重跑到成功再隐藏失败。
