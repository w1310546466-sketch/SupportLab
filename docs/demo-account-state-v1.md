# 虚构服务 Demo API v1：账号快照与 429 证据

- 文档 ID：`demo-account-state-v1`
- 服务版本：`demo-api-v1`
- 数据版本：`account-states-v1`，关联 `requests-v1`
- 编制日期：2026-09-30
- 性质：全部为 SupportLab 人为构造的演示规则，尚未作为保留评估集封存；不代表真实供应商。

## 查询约定

`get_account_state` 的外部参数为 `request_id`。可信账号由应用上下文提供，用户或未来模型不能用工具参数指定另一个账号。
结果为请求发生时的历史快照。`captured_at` 必须等于该请求的 `occurred_at`，服务版本也必须相同。
本版本只支持精确对应，不进行“最近一次快照”或“当前实时状态”的替代。
未知编号、跨账号请求、缺失或不匹配快照均返回 `not_found`，没有账号信息。

## 字段口径

| 字段 | 含义 |
| --- | --- |
| `request_id` | 该快照对应的模拟请求编号 |
| `service_version` | 适用的虚构服务版本 |
| `captured_at` | 快照时间，ISO 8601 UTC；不是工具查询时间 |
| `rate_window_seconds` | 演示频率统计窗口长度，单位为秒 |
| `rate_limit_per_window` | 窗口内允许的请求次数 |
| `requests_in_window` | 窗口内尝试的请求次数，包含本次尝试和被拒绝的请求 |
| `monthly_quota_limit` | 本月允许的成功请求总数 |
| `monthly_quota_used` | 本月已计入用量的成功请求数；被拒绝的请求不增加此值 |
| `quota_resets_at` | 构造的月度配额重置时间（UTC） |

当 `requests_in_window > rate_limit_per_window` 时，数字支持“本次请求触发频率限制”。
等于上限表示尚未超过频率阈值。
当 `monthly_quota_used >= monthly_quota_limit` 时，数字支持“本月没有可用于下一次请求的配额”。
同一快照可以同时不满足多个限制，应结合请求错误码和其他证据解释，不能只看 429 就断定余额不足。
本版不提供余额或权限字段；缺失数据不能替换为零或视为一切正常。

| 请求 | 时间（UTC） | 窗口请求数 / 上限 | 月度已用量 / 上限 | 可核对的请求错误码 |
| --- | --- | --- | --- | --- |
| `req_demo_017` | 2026-09-27 02:00:00 | 61 / 60 | 999 / 1000 | `RATE_LIMIT_EXCEEDED` |
| `req_demo_018` | 2026-09-27 02:01:00 | 2 / 60 | 1000 / 1000 | `MONTHLY_QUOTA_EXHAUSTED` |

两条请求属于 `acc_demo`，不是同一时间的相互矛盾状态。
演示设定：两条记录之间频率窗口已推进，并发生过一次成功调用，将月度用量从 999 增至 1000。
这次中间调用未单独加入三条请求种子记录；当前数据不是完整流量日志，工具也没有计算整个请求历史。

另有 `acc_other` 的 `req_other_001` 快照用于访问范围测试；当前演示账号不能查询它。
其频率和配额数字不用于解释 403；权限信息仍待后续补充。
