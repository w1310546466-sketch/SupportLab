# 模型回复格式错了，Agent 怎样有限纠正

2026-10-06。继续只学习 Agent 的失败恢复、行为边界和运用 AI 的方法。

阅读提示：本文保留 10 月 6 日中间阶段的实验记录，测试数量与“尚未验证”均对应当时状态，不代表当前最新结论。最新概况见 [README](../README.md)；后续观察到的真实格式纠正案例见 [对照实验](optimization-2026-10-06.md)。

## 一个具体例子

上次排查 `req_demo_018` 的缺快照变体时，模型已查到请求，账号工具也返回“未找到”，但最终回复无法被程序解析。本来已经收集的证据不应该因此丢掉。

现在的处理是：**保留工具证据 → 记录格式问题 → 在预算允许时要求重新组织一次 → 再检查格式和证据 → 通过才发布，否则停止。**

例如我们在离线实验中故意给回复套上代码围栏：外面多了三个反引号，里面才是答案。程序不猜测截取哪一段，而是让模型按约定重新提交一个答案对象。
这个围栏例子是本次构造的，不能据此断言上次真实失败也是围栏造成的；旧报告没有保存足以确认具体格式问题的信息。

这里不用先学 JSON 语法。你只需理解：程序与模型约定了交付格式，模型有时没有遵守，程序需要能识别并处理这种失败。

## “纠正一次”有哪些边界

- 一次任务最多给一次格式纠正机会；它算一次模型请求，也消耗 token。
- 仍受原来的总请求数、输入大小和时间限制。若总预算已用完，即使纠正机会没用过，也不能追加调用。
- 已查到的工具结果原样保留；无法解析的回复原文丢弃。新日志只保存错误类别、字符数、行列位置、是否以围栏开头等格式信息，不保存回复原文或密钥。
- 纠正阶段只允许重新提交最终答案，提出的工具调用不会执行。第二次仍格式错误就停止。
- 格式合法之后，仍要经过原有的诊断/停止理由检查。格式改对不能使无依据的结论变得正确。
- 网络超时、认证失败、输出截断、证据不支持等情况，不套用这次格式纠正策略。SDK 自身的网络自动重试仍关闭。

我们只允许纠正可被程序识别的最终对象格式错误：语法、顶层不是对象、重复字段、非标准常量、过深嵌套或过大内容。有效对象的字段结构、原因和证据，由后续原有检查负责；这些检查失败不会再次请求模型改答案。

内部实现中，一次本地决策可以包含原请求和一次格式纠正。因此“本地决策轮次”“模型请求次数”“工具执行次数”需要分别记录，不能相互替代。

## 实际验证

程序检查 **158/158** 通过，原 mock 场景 **20/20** 通过；新增 **6/6 离线实验**符合预期：

| 构造情况 | 实际观察 |
| --- | --- |
| 第一次格式错，纠正后格式与理由都正确 | 接受停止理由，共 3 次模拟模型请求，其中纠正 1 次 |
| 纠正后仍格式错 | 停止，共 3 次模拟模型请求，不发第 4 次 |
| 原总预算只有 2 次，且已经耗尽 | 不发送纠正请求，保留证据停止 |
| 明确关闭纠正功能 | 第一次格式错就停止，仍有诊断信息 |
| 格式改对，但已给编号却谎称“缺编号” | 原证据检查拦下，不把格式成功计为任务成功 |
| 纠正时又提出查工具 | 阻止执行，原来的 2 次工具结果保留 |

这些实验使用生产适配器和实际本地工具，但模型回复由脚本提供。报告明确标为 `offline_adapter`，真实 API 次数为 0，token 用量为未知，不伪装成真实模型评估。

本次另做了一次真实 DeepSeek 缺快照试跑，**1/1 符合该开发场景要求**：

1. 模型同批提出查请求、查账号；程序实际执行，分别返回成功和未找到。
2. 模型下一轮正确提交“缺账号快照，需人工核实”的停止理由。
3. 程序检查通过，生成交接说明。

实际为 **2 次模型请求、2 次工具、3 轮本地决策**，约 **5.38 秒**；输入 **3117**、输出 **97**、总计 **3214** tokens。
这次**格式纠正次数为 0**，所以不能证明真实纠正分支已生效，更不能把与上次的差异解释为纠正机制提高了成功率。原始系统提示词未改变；纠正提示只有遇到格式失败才会发送，本次没有发送。

重点比较 `recovered`、`budget-used`、`unsupported-reason`。先预测每个例子会不会通过，再读结果，分别指出“格式检查”“证据检查”“预算检查”哪一个决定了最终行为。

参考答案：第一个两项内容检查都通过；第二个预算先阻止追加调用；第三个格式通过，但停止理由被证据检查否决。能解释这三种区别，就达到本次练习目标，不要求补通用基础课程。

> 加入一次格式纠正，并验证预算用完时不会多调用。不要放宽证据检查。报告每次实际请求与纠正次数；如果真实运行没有触发纠正，请明确写出，不能把通过归因于纠正机制。
